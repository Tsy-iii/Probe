# Probe 中文文档

Probe 是一个本地接口测试执行与失败证据工作台：从真实 pytest 用例目录选择执行范围，后台运行测试，保存任务状态、尝试、报告与请求／数据库证据。

主项目介绍与启动命令有对应版本：[中文 README](../README.zh-CN.md)／[英文 README](../README.md)。工作台界面和本目录的操作指南目前以中文为主。

## 先启动，再完成一次回归

1. 按 [快速开始](../README.md#quick-start) 准备虚拟环境、PostgreSQL 和四份数据库，初始化订单与平台表。
2. 分别启动平台 API、Worker 和前端。手动操作订单时再启动 8002 订单 API。
3. 打开 <http://127.0.0.1:5174>，选择「真实 HTTP 订单测试」或「演示订单接口回归」，查看用例并提交。
4. 在结果中展开请求、响应、检查项和数据库前后快照。测试结束后数据会清理，报告保留证据。
5. 选择「金额计算故障对照」，观察故障实现对应的失败；这里应保持 failed，不代表平台故障，也不表示平台自动修复业务代码。

首次启动不会附带任何人的历史任务。任务、报告链接和 Worker 状态都由你本次运行产生。

## 数据位置

| 数据库 | 用途 |
| --- | --- |
| `probe` | 手动演示商品、订单和支付事件 |
| `probe_test` | 自动测试的临时订单 schema |
| `probe_platform` | 真实工作台任务、尝试和报告 |
| `probe_platform_test` | 平台集成测试；演示接口回归的临时平台 schema |

默认数据库地址为 `127.0.0.1:5433`。使用其他实例时同时检查 `.env` 中四项连接配置，保持库名和用途隔离。Compose 的初始化 SQL 只在新数据卷第一次启动时运行；已有实例缺少测试库时，应按 `scripts/init-test-db.sql` 的数据库定义补齐，而不是删除数据卷重置。

## 启动后常见问题

- 任务一直等待：查看环境面板的 Worker 心跳；API 和 Worker 是两个独立进程。
- 演示操作无法读取：确认 8002 服务已启动，且其库名／schema 与数据页一致。
- 测试数据看不到：测试结束后临时 schema 已清理；在报告中查看保存的快照。
- 只有部分用例显示：确认当前的用例选择和报告筛选；历史报告保留提交时范围。
- 数据库可连接但测试失败：环境就绪只说明运行条件满足，仍以实际业务断言为准。

仓库不提供登录、多租户、真实支付或生产部署配置。当前执行器仅面向可信测试；进程和数据隔离不等于安全沙箱。
