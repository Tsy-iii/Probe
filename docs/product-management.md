# 演示商品管理

> 当前入口见 [主 README](../README.md)；文末旧验收数字和截图为有日期的历史记录，不代表当前服务状态。`.local/` 与 `test-results/` 仅为运行产物位置，历史原始文件不随仓库发布。

入口：[数据浏览](http://127.0.0.1:5174/#data) →「订单演示数据」→「商品」。这些操作只管理演示库，自动测试仍在 `probe_test` 的随机 schema 中准备商品，不依赖演示商品的价格、库存或删除状态。

## 页面操作

1. 点击「新增商品」，填写名称、单价（元）及可售库存，再保存。首次打开只显示填写提示，离开字段或提交时才显示错误；错误字段修正后反馈消退。金额最多两位小数，后台存储整数分；库存可以为 0。普通新增保留商品列表并选中新行；只有商品数量达到加载上限时才使用有明确标识、可清除的定位视图。
2. 点击商品只打开详情，保持当前表格、搜索和筛选。在详情中选择「编辑价格与库存」，已有订单金额保持下单时的值，后续订单使用新价格。只有点击「查看关联订单 →」才切换到订单表并按该商品筛选。
3. 在详情里点击「删除商品（可恢复）」并确认。删除采用 `is_active=false`，不物理删除商品，不清空价格或库存，不删除历史订单和支付事件。新订单被拒绝，错误码为 `product_inactive`。
4. 切换「已删除」，打开商品详情并点击「恢复商品」。恢复同一个 ID，保留当前价格及库存；删除期间旧订单取消所恢复的库存也保留。

「在售 / 已删除 / 全部」按实际状态筛选。图表只展示已加载的在售商品，库存窗口固定显示两条完整记录，其余通过右侧列表内部滚动查看；左侧订单图、两侧标题与说明保持固定。图表数据有行数上限，不能用已加载数量替代全表数量。

表单存在未保存内容时，关闭、取消或 Esc 会显示「继续编辑 / 放弃修改」，避免误操作丢失草稿。保存过程中不可关闭或重复提交。价格／库存发生冲突或保存结果未确认时，阻止继续提交，须先读回核对；新增结果未确认时，应返回列表刷新确认，避免重复新增。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/data/products` | 新增商品 |
| `GET /api/data/products/{id}` | 读取当前值，包含已软删除商品 |
| `PATCH /api/data/products/{id}` | 修改价格及可售库存 |
| `DELETE /api/data/products/{id}` | 软删除；重复调用不重复改变状态或库存 |
| `POST /api/data/products/{id}/restore` | 恢复；重复调用不回滚后来的价格、库存调整 |
| `GET /api/data/orders?focus_product_id={id}` | 同一只读快照中定位商品，完整计数保留 |

新增请求：

```json
{"name":"Probe example","price_cents":"2999","stock":6}
```

价格用十进制整数字符串传输，数据库使用 bigint，避免经过 JavaScript 浮点数后丢失精度。名称须为 1～100 个非空字符；价格为 1～9223372036854775807 分；库存为 0～2147483647 的整数。

修改请求必须带上读取时的原值：

```json
{"price_cents":"2490","stock":8,"expected_price_cents":"1990","expected_stock":5}
```

后端以商品 ID、原价、原库存及在售状态作单条条件更新，并在 PostgreSQL 事务提交后才返回成功。价格或库存已变时返回 409，页面提示重新读取；不会自动重试写入。重新读取会放弃草稿，再按最新值明确填写。网络异常或超时不等于事务必然回滚，页面提示保存未确认，应先读回核实。

## 数据迁移与边界

老环境执行：

```bash
.venv/bin/python -m probe.manage migrate-db
```

脚本 `migrations/order_0001_product_active.sql` 只添加默认在售的 `is_active` 列，可重复执行，不重置旧数据。新环境的 `init-db` 同时兼容此列。平台 Alembic 链仍为 `0004_rerun_source`，与订单库迁移分开。

新增 ID 使用 PostgreSQL 序列。为兼容历史手工插入的商品 ID，只在低频新增操作中短暂持表锁并按需推进落后的序列。库存扣减仍使用行级原子更新。高频商品创建可在规范化种子初始化后进一步减少锁范围，当前选择适合小型演示服务。

编辑比较当前价格和库存，没有追加版本号或历史库存流水；变化后又回到相同值不会被识别为不同版本。软删除和恢复只改变状态，因此不会覆盖期间合法的订单库存变化。

开发环境默认开放，可用 `PROBE_PLATFORM_DEMO_EDIT_ENABLED=false` 关闭后重启平台 API。`APP_ENV=production` 始终禁止商品写入。实际页面仅允许演示库；集成测试通过应用工厂显式注入 `probe_test` 的独立 `case_` schema 验证。工作台的演示接口回归只在测试工厂中允许与 attempt ID、订单 schema 和平台测试 schema 全部一致的 `run_` 空间；测试库 public、非本次尝试空间和平台记录不开放编辑。详见 [演示回归隔离说明](demo-suite.md)。
